# 로컬 공고 마감일·목록 삭제 정책

마감일은 사용자 지정 → 공식 마감일 → 게시일+21일 → 최초 수집일+21일 순으로 결정한다. 기관별 예외는 없으며 상시모집도 같다. 날짜를 파싱할 수 없으면 다음 근거로 넘어가고, 전부 없으면 UNKNOWN_DATE로 표시한다.

한국시간 기준으로 공식·사용자 마감일은 당일을 포함한다. 자동 마감은 기준일에서 21일이 지난 날짜의 00:00부터 적용한다. 예: 10월 1일 게시 공고는 10월 21일까지 보이고 10월 22일부터 마감이다. 자동 마감 시작일과 공식 원본 날짜는 화면에서 구분한다.

- 현재 공고: A단계 표시 대상 중 미삭제·마감 전 공고. UNKNOWN_DATE는 날짜 미확인 표시와 함께 유지한다.
- 마감된 공고: A단계 표시 대상 중 미삭제·마감 공고.
- 삭제한 공고: notice_id 기준으로 숨긴 공고. 마감 여부와 A 결과에 관계없이 확인·복원 가능하다.
- 기존 ‘제외된 공고 보기’ 체크박스: 현재/마감 보기에서 A 제외 공고도 함께 확인한다. 날짜를 연장해도 A 제외가 적격으로 바뀌지는 않는다.

카드와 상세 화면의 ‘마감일 설정’에서 날짜를 저장·수정·해제한다. 해제하면 다음 우선순위로 되돌아간다. ‘목록에서 삭제’는 로컬 숨김이며 ‘복원’은 삭제 상태만 해제한다. 복원 시 마감된 공고는 마감 보기에서 확인한다.

사용자별 공고 캐시 옆 `*.notice-settings.json`에 origin별 notice_id, user_deadline, deleted_from_list, updated_at을 보관한다. UTF-8 임시 파일을 fsync 후 os.replace하여 원자적으로 저장한다. 잘못된 파일을 빈 값으로 덮어쓰지 않고, 읽기 오류 시 목록 표시와 설정 변경을 차단한다. 회사 DB와 경로 충돌도 거부한다.

중앙 history는 보존한다. feed v3 형식은 그대로 두고 사전 필터 통과 공고를 마감 여부만으로 제거하지 않는다. 따라서 로컬에서 마감 공고 조회·날짜 연장이 가능하다. 21일 자동 마감·사용자 날짜·목록 삭제는 중앙에 저장하거나 전송하지 않는다. A/B 캐시와 matcher 입력·계산식도 변경하지 않는다.

검증: `python -m unittest discover -s tests -p test_notice_settings.py`, `python -m tools.eligibility_projection_smoke`. Windows EXE는 `--notice-settings-smoke-report <report.json>`으로 합성 공고·임시 경로에서 날짜 편집, 삭제·복원, 동기화, 재시작, A/B 캐시·matcher 불변을 검증할 수 있다. 실제 회사 DB는 사용하지 않는다.
