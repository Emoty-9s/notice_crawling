# 수출바우처 Actions 안정화 진단 (2026-11-09 17:16 KST)

운영 결론은 **비활성 유지**다. 최종 전용 검증에서도 HTTP 응답 전에 연결이
재설정됐다. 서버/네트워크의 GitHub 실행 경로 접근 제한이 의심되지만, 정확한
제한 정책이나 원인은 확인되지 않았다. 요청 속도나 OpenSSL 버전이 원인이라고
단정하지 않는다. 중앙 workflow는 수정하거나 실행하지 않았다.

## 코드와 검증

- 기존 scraper의 목록/상세/페이지/ID 로직은 재사용했다.
- `ExportVoucherSession`에서 성공/실패 후 요청 간격을 적용한다(기본 5초).
  기존 GET의 제한 재시도와 지수 백오프를 유지한다.
- 알려진 첨부 위젯이 빈 배열을 반환하면 공개 상세부터 **한 번만** 재조회한다.
  위젯이 없는 실제 첨부 없음과 구분한다. 계속 빈 배열이면 실패다.
- 파일 다운로드의 연결 오류·빈 응답·HTML 오류는 공개 상세와 첨부 목록부터
  **한 번만** 복구한다. HTTP 403과 인증서 검증 실패는 재시도하지 않는다.
  성공한 다른 파일은 다시 다운로드하지 않는다. 크기·시그니처 검증은 유지한다.
- 성공 OCR/완료 리소스 재사용, 실패 파일 후속 재시도와 기존 부분 텍스트 보존은
  기존 extraction/pipeline을 사용한다. 원본 첨부는 메모리/자동 삭제 임시공간만
  사용한다. A/B, matcher, 21일 정책, 사용자 DB/history/OCR 캐시 로직은 변경하지 않았다.
- 계측은 경로·단계·상태·바이트 수·예외 분류·경과 시간·논리 요청 시도/재시도
  횟수·세션 순번·연결 재사용 여부만 기록한다. URL 쿼리·쿠키·토큰·본문·예외의
  원문 문자열은 로그에 출력하지 않는다. 환경 정보는 버전/정책만 기록한다.
